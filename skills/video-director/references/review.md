# 可选的可视检查工具

先按作品需要决定怎么检查。静态排版、连续动作、复杂遮罩和数据内容的风险不同，不要求固定镜头数、关键帧数量、采样频率或审批节点。

使用附带工具时，页面暴露window.DUR、render(t)、READY。render可乱序调用，字体与资源就绪后READY。使用其他工具链时遵循它的等价合同，不必重写工程。

可选inspect(t)可提供几何与项目自定义断言：

```js
{crop:[left,top,right,bottom],annotations:[{
 text:'对象名称',anchor:[x,y],box:[x,y,width,height],alpha:1
}],assertions:[{name:'当前项目的验证项',passed:true,message:'可选说明'}]}
```

断言结果应来自实际状态或独立计算，不为通过检查而写死。没有内容验证断言时，工具只验证已提供的几何，不声称已验证内容正确；缺少inspect时只生成审片材料。

review命令提供便利的默认采样策略，可用--step调整采样间隔，或用项目自有脚本/手工选择更合适的检查时刻。输出review.json和可离线放大的review.html。它们是检查材料，不是强制创作步骤，也不代表已人工观看或试听。

实际观察画面后再判断构图、字体、动作、遮挡和与需求的一致性；需要时复核最终编码。技术检测、视觉判断和声音试听分别说明实际完成范围。
